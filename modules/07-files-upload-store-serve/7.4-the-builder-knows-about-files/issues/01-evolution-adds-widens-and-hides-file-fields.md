# Evolution adds, widens and hides file fields

Status: done

## Epic

Module 7 — Files: Upload, Store & Serve · Epic 7.4 — The builder knows about files
(PLAN decisions 5, 34 and 35; ADR-0009: `modules/07-files-upload-store-serve/PLAN.md`)

## What to build

An existing capability can gain file fields, let a file field take more families, and
hide a file field. None of these destroys a record or a file.

**Adding is additive.** Evolving a capability to add a `file` or a `file[]` field adds a
nullable TEXT column. Older rows read `null` for a `file` and `[]` for a `file[]`. The
evolution Gate carries its behavioral tests forward with file tokens, and the input
digest decides which tests are reused.

**Widening regenerates the renderer when it has to.** Widening `accepts` is ordinary
evolution. When the field is on the card, the item renderer is regenerated, because a
card written for photos was never written for video. Narrowing is already refused by
7.2/02.

**Hiding keeps the bytes.** Evolution never destroys. A hidden file field's keys stay
`owned` until capability deletion collects them through 7.3/05's adapter. A form that
still holds a pending key for a field evolution just hid is refused with a sentence
rather than a wire error.

**`file` ↔ `file[]` is a type change, and it is refused.** The existing rule that a
committed field's type never changes already refuses it, in candidate validation. This
issue adds the test.

**What 7.1/08 left for a required file field.** A file field may be required since 7.1/08,
and the save refuses a record whose required file field would end up empty, a record that
already held nothing included. An evolution that adds a required file field, or makes one
required, therefore leaves every older record refusing every edit until a file is added to
it. A record has no default file to backfill, so this issue decides what the evolution does
about those records.

## Acceptance criteria

- [x] Evolving to add a `file` and a `file[]` field keeps every existing record, which
      reads `null` and `[]` respectively
- [x] Widening `accepts` on a field that is on the card regenerates the item renderer;
      widening one that is not on the card does not. The test widens `["image"]` to
      `["image", "document"]`, since today that evolution keeps a card that draws a PDF
      as a broken `<img>` (found in 7.2/05's review)
- [x] Hiding a file field leaves its keys `owned` and their bytes in place
- [x] A save holding a pending key for a just-hidden field is refused with a platform
      sentence
- [x] A candidate that turns `file` into `file[]`, or the reverse, is refused, with a test
- [x] Carried-forward behavioral tests with file tokens are reused or regenerated by
      their digest
- [x] `bun run test`, `bun run typecheck`, `bun run lint` clean

## Living demo

On the Aluna running on `:3030`, build Notes without files and add three notes. Ask
Aluna to "let my notes hold attachments". Notes evolves with a many-file field, and the
three notes are still there. Attach a PDF to one and save. Ask to let the attachments
include videos: the card is regenerated. Ask Aluna to remove the attachments: the field
hides, and the PDF's bytes stay in `storage/`. Ask to make a single-file field hold many
files: the change is refused.

## What landed

**Widening redraws the card.** `file_families` is now a field-scoped fact in
`src/builder/evolution/diff/diff-engine.ts`. It moves admission and the writing suites as before,
and adds the `item` unit when the field is in `item.shows`, so design lint runs too. The four facts
that change what a card draws (`field_label`, `choice_values`, `choice_option_labels`,
`file_families`) share `contributeDrawnFieldFact`, and the shown-field check sits once after it.

**A stale form gets a sentence.** `parseCapabilityRequest` (`src/runtime/router/wire/
wire-protocol.ts`) parses every field the spec holds, hidden ones included, so a malformed request
stays a 400. Only then does `refuseStaleForm` throw `FormChangedError` for a form naming a hidden
field (file or not, a pending upload included) or a create leaving out an active non-file field.
`asFormChanged` turns a `missing_required_fields` refusal for a field the form never drew into the
same error. The router answers `formChangedFailure`: 422, retargeted, the new platform-owned code
`form_changed`, and "I changed {label} while this form was open. Mind closing {label} and opening
it again?". A create form is drawn only with its window, so closing it is the remedy that works for
both forms. A create carrying no markers at all stays a protocol error, since every control posts
one.

**The required-file decision (PLAN 35a).** The owner chose Module 4's rule: an evolution may add a
required file field, or make one required; older records read `null` or `[]` and refuse every save,
naming the field, until a file is added. No invented file, no weakened requirement, no refused
evolution.

**Already in place, now proved.** The nullable column, `NULL` read as `[]`, the type-immutability
refusal of `file` ↔ `file[]`, hides keeping keys `owned` (nothing in evolution touches the ledger),
and digest-based reuse.

**Tests.** `evolution-matrix.file.test.ts` (end to end through the engine: add `file` and
`file[]` over three records, a required file field, widening on and off the card, a hide keeping
an owned key and its column, `file` ↔ `file[]` both ways), `behavioral-test-freeze.file.test.ts`
(file-token suites reused or regenerated by digest), `router.file-hidden.test.ts` and
`wire-protocol.stale.test.ts` (the refusal and every stale and malformed shape), plus the
`file-evolution.test.ts` widening rows and a `form_changed` producer in `refusal-rescue.test.ts`.

**Docs.** PLAN decisions 34 and 35a, and the stable-codes sentence in `docs/architecture.md`.

## Findings from adversarial review, all fixed

Three passes (Opus): the change, the fixes, then the fixes of the fixes.

- "Mind opening it again?" sent a create form into a loop, since the create panel is drawn once
  with the window (MAJOR). The sentence now names the capability and asks to close and reopen it.
- The hidden-field check ran before the protocol checks, turning malformed requests into
  `form_changed` (MINOR). Hidden fields are now parsed like any other and refused last.
- A presence-only hidden `file[]` and a hidden non-file field had no test (MINOR, twice). Both do.
- A create form drawn before a field was added failed with an unshown 400 (MINOR). It answers
  `form_changed`.
- A stale form after a file field became required got a sentence naming a field it never drew
  (MINOR). It answers `form_changed`, at once even when another missing field was drawn (INFO).
- The ordering fix made a hidden `string[]` answer 500 (MAJOR, second pass). A hidden list keeps
  its rows unparsed until the stale form is refused; tested in both posted shapes.
- Doc drift on `form_changed` (MINOR); a markerless create (INFO), a capability with every field
  hidden (INFO), a missing return type, dead code and field names echoed (INFO). All fixed.

## Verification

`bun run test` 4575 pass, `bun run typecheck` and `bun run lint` clean. Live on `:3030` with real
builds (gpt-5.6-terra), on a new Studio notes capability, since the desk already holds a notes
capability the resolver would otherwise evolve.

Live, each step a real build from the prompt bar:

- v1 → v2 "let my studio notes hold attachments": a nullable `attachments` `file[]` column; the
  three older notes read `attachments=[]`. A PDF attached to Kiln log saved `owned`, bytes in
  `storage/`. The model chose all four families, so no widening was left on that field.
- v3 "one cover photo, shown on its card": `cover_photo` `file`, `accepts: ["image"]`, on the card.
- v3 → v4 "let a cover also be a PDF": `file_families` only; `unitAttempts` shows `item`
  regenerated (9,865 tokens) and every Handler copied (0 tokens); design lint passed; the new card
  draws `kind === "document"`.
- v4 → v5 "stop keeping attachments": `attachments` hidden. The Kiln log key stayed `owned`, its
  column value and its bytes in place. A second tab's edit form, drawn at v4 and holding a pending
  PDF, answered 422 `form_changed` with the sentence, shown at the top of the form. Leaving that
  form let the pending upload go (row and bytes removed); reopening Studio notes drew a fresh form.
- v5 → v6 "turn the cover into a field that holds many": nothing changed type. The model kept
  `cover_photo` a `file` and added a new `cover_photos` `file[]` instead of a refused retype.

Two observations for sign-off, not defects of this issue's mechanics: "stop keeping attachments"
also hid `cover_photo` (the candidate model read "attachments" broadly), and the retype request was
met with a sibling field, where the living demo expects a refusal.
